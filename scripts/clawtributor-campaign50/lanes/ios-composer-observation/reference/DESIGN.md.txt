## Hard bounds and capture

At most2048 records per app process, nesting depth32, four text fields per record limited to64 UTF16 code units each, and at most8 ranges per snapshot. Preserve every captured range location/length losslessly as decimal strings of the native Swift integer values exactly as returned, including the exact NSNotFound sentinel and without signed/unsigned reinterpretation, plus the UTF16 text length. Do not clamp, normalize, coerce through a floating-point JSON number, or silently truncate ranges/text. If the range count, text length, record count, depth or output bound is exceeded, set overflow=true and incomplete=true with the breached limit and stop recording payloads without throwing into the application. Preserve already captured records and explicitly report that capture stopped. An incomplete trace is not usable causal evidence. Serialized output is capped at8MiB. IDs/enums are fixed scalar fields; retain no view hierarchy, arbitrary object description, credentials or external data. This fixture has only synthetic composer input; protected question-field contents are outside this owner.

Drain **after the case's existing actions/assertions and records**, in UITest tearDown immediately before the existing app termination. Use a fresh diagnostic nonce appended only as launch metadata, then a test-owned Darwin notification request/ack pair. The host's private recorder registers its exact nonce-specific request during construction; no userInfo payload is used. The UITest registers the matching acknowledgement observer before posting its drain request. The callback schedules one MainActor drain after the case and seals the buffer only at nesting depth0, after every open observation span has closed. If received while a span is open, drain remains pending until depth0; it must not serialize a half-open span or alter the UI operation. The sealed buffer is immutable. Serialize it atomically into the app's temporary container with an envelope binding nonce, app PID, case, final sequence, bounds and complete/incomplete status. Acknowledge only after successful atomic file creation; serialization/write failure must not send a success acknowledgement. The test waits at most3s for this non-UI capture, within the unchanged120s case allowance and without extending any UI deadline. Register/post/wait/ack timings and drain outcome are separate capture metadata. Preserve original native assertion outcomes verbatim: missing acknowledgement, incomplete trace or failed file verification is a capture failure, never a replacement native assertion or an accepted baseline.

The external runner copies only that nonce's trace from the known test bundle's container on the owned Simulator before the next case, and binds its hash/PID/nonce/case to the existing native result. No extra AX lookup, tap, paste, type, focus change or app relaunch is introduced. ## Verified contracts and perturbation limits

Apple's iOS26 UITextViewDelegate contract says its multi-range shouldChange callback permits the requested replacement when true; if neither new nor legacy callback is implemented, true is assumed. The new callback therefore preserves the documented decision, **not necessarily the same internal callback path or timing**. Adding responds-to-selector participation and didChangeSelection notifications may perturb UIKit. It must not be called automatically behavior-neutral. [Delegate contract](https://developer.apple.com/documentation/uikit/uitextviewdelegate/textview(_:shouldchangetextinranges:replacementtext:)). I also read the installed SDK's UITextView.h; the actual26.6 SDK signature must be captured before compilation admission.

UIView.sizeThatFits is documented to calculate a size without resizing the receiver; this does not promise that UITextView/TextKit internal state or selection never changes. Thus a before/after difference is a measured causal lead, not evidence that measurement is already the bug. [Measurement contract](https://developer.apple.com/documentation/uikit/uiview/sizethatfits(_:)). No sizeToFit/layoutIfNeeded/frame/contentSize probes are added.

CoreFoundation's inspected header documents Darwin notifications as system-wide, requiring a running main run loop and carrying no object/userInfo. Hence nonce-specific names and a run-loop-friendly bounded XCTest expectation are required; no semaphore blocks the receiving main loop. This is diagnostic transfer only, not an app authorization/data API.

Even buffering, extra property reads and notification callbacks can alter scheduling or Observation dependencies. **Nonreproduction and newly different corruption both remain potentially perturbed/inconclusive.** A positive trace is a causal lead only: identify the earliest divergence and its enclosing span, do not infer cause from nearby events alone. It cannot count as a fix or replace confirmation on the unchanged uninstrumented original flow. Any later repair needs an independently reviewed minimal cause plus original uninstrumented failure/green confirmation, with no slower typing, shorter draft, larger waits or weaker equality check.
