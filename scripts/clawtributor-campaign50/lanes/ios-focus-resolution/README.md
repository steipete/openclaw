# iOS focus dependency capture — not UI proof

This separate packet preserves the accepted c2 host/project/test bytes and does not change or execute that baseline packet. Controller fields use mode `baseline` only as the existing transport envelope; `PROOF_VARIANT=resolution-only` and the separate directory/entrypoint are mandatory. Success means a candidate dependency lock was captured. It never means admission, a reproduced defect, or a passing UI test.

The approved secretless Mac route supplies Xcode26.6 build17F113, XcodeGen2.46.0, Node24.20.0, pnpm12.3.4 and canonical Mermaid resources. The driver verifies frozen source a1707cb3, the accepted host-packet hash, every copied host/project/test hash, and the source dependency declarations. It generates the real test-host project and invokes only `xcodebuild -resolvePackageDependencies` for generic iOS Simulator. It does not select/create/boot a Simulator, build an application or test bundle, sign, launch, or run a UI test. SwiftPM's manifest/resolution work is untrusted code and therefore only runs remotely after route/packet review and root dispatch.

The shared/iOS package has no tracked Package.resolved. First resolution captures the complete generated lock. All remote packages must carry distinct identities and immutable40-hex Git revisions; direct repository/version requirements must match the exact reviewed Package.swift (ElevenLabsKit0.1.1, GRDB7.11.1, SwiftMath1.7.3, swift-markdown0.8.0). Transitive pins are captured, not silently approved. The full raw lock, generated project, source/host/toolchain hashes, commands and raw logs remain available for independent review. The lock hash and immutable pin list are emitted in RESOLUTION-CANDIDATE.json with admitted=false.

Root and the independent reviewer must admit the captured revision set before a baseline or candidate build. A separately reviewed locked baseline packet will carry those exact Package.resolved bytes and an admission manifest naming their SHA256, source Package.swift hash, accepted host/project hashes and originating hosted receipt. It will install that lock into the generated project's canonical workspace location **before** any build, use `-disableAutomaticPackageResolution` and `-onlyUsePackageVersionsFromResolvedFile`, and verify unchanged lock bytes/revision set afterward. No unlocked resolve fallback is allowed. Candidate uses that same admitted lock and otherwise unchanged host/tests/toolchain; only the authorized one-line product repair may differ after actual red. The old c2 driver must not be dispatched for paired proof because it resolves immediately before testing.

Failure retention is deliberate: logs are written before every command; any produced lock is copied before the resolution exit is classified; receipt and exit-code are written on every caught failure; generated work/checkouts remain until the disposable runner is torn down. Partial or schema-mismatched locks stay unadmitted. No real data, credentials, private signing configuration or product fixture flag is used. Generic Mac bootstrap retains its own failed-phase/source receipts. No local package resolution, signing, build, Simulator action or target execution was performed while authoring this packet.

The eventual locked UI packet must preserve/export matching app-only screenshot attachments from the accepted tests (ready/post-tick/typed/passive/failure), with source and Simulator receipts for the final PR's inspected before/after pictures. This preflight introduces no UI action or timing change.
