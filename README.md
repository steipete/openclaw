# Permanent Windows installer regression proof

This temporary proof-only branch runs `node scripts/run-vitest.mjs test/scripts/install-ps1.test.ts` through OpenClaw's canonical project routing on a GitHub-hosted `windows-2025` runner. It proves the actual permanent regression test, separately from the already-successful 24-case extraction-owner proof in [run 33674548373](https://github.com/steipete/openclaw/actions/runs/33674548373). That matrix is not repeated.

The original source is frozen at `af531525c46444521986002d64b888ee5ed097cb`. Only its permanent test file is replaced with the exact published test bytes from PR #135410 head `edb35c6c96346b573bb6389cba40dcdba273fe56`; production and tooling stay original. The after checkout is that exact published head, with its test file unchanged. The same test bytes have SHA-256 `2a31256c47e51ebbe8d50b5560498d01f2aa312cc9880c09f4115b2f54656ab1`. Full Git trees and relevant source/lockfile hashes are pinned in `bindings.json`. The controller snapshots the complete index entries, flags and index bytes, plus every tracked file or symlink, before execution. The original checkout admits only the exact test-file overlay; the repaired checkout and proof assets admit no tracked changes. Complete guards run after overlay admission, after installation, after testing and at final verification. Index snapshots, dependency lockfiles, all tracked bytes, the binding file and the proof manifest must remain unchanged through their admitted phases; receipts retain actual differences on failure.

A pass requires the original run to fail only `reaches portable Node ZIP fallback after redirected native tar stderr`, with the actual native stderr error in its Vitest assertion output. The after run must pass that case and preserve all sibling test outcomes. Missing test execution, a skipped target, unexpected failures, incomplete JSON, process failure or cleanup failure cannot count as proof. The existing Windows-only test runs its fixture under Windows PowerShell 5.1 and PowerShell 7; its new case asserts argv, exit 17, extracted bytes, partial-output removal, fallback temporary-directory cleanup, stderr preservation, and restored caller preference/location.

The workflow uses Bash, matching the upstream Windows job's default shell. The child receives an allowlist of native Windows prerequisites, including the runner's unmodified `PSModulePath`; no PowerShell 7 parent launches Python. There are no injected module imports, module maps, test assertions, timeout overrides, runtime skip flags or native-error preferences. Each checkout gets its own fresh HOME/USERPROFILE/AppData/temp, Corepack cache, pnpm store and cache. Secrets and GitHub action credentials are omitted from the install/test environment. Actions use read-only repository permissions and checkout does not persist credentials.

Node is pinned to `22.22.3`, the supported 22.x line used by upstream Windows CI; its executable hash is checked against the official Node distribution. Its bundled Corepack creates pnpm shims only in the task's temporary bin directory and selects the repository's exact `pnpm@12.1.0` integrity pin. Each checkout runs a separate frozen-lockfile dependency install with the ordinary Windows lifecycle scripts enabled. No dependency cache is shared between before and after. There is no build override, test-only loader or local execution.

Setup/install/test stdout, stderr, command receipts, canonical Vitest JSON and the final verdict are retained even on failure. Install processes are bounded to 15 minutes and test commands to 8 minutes without changing any internal repository timeout; each command has a 16 MiB combined output bound. The owner kills only its own process tree if an outer bound is reached. Temporary profiles/caches are removed before the final verdict, and the hosted checkouts are disposed with the runner. Artifact retention is 14 days.

This verifies the permanent test and the repaired extraction owner. It does not install an actual Node distribution, run an unmocked full installer, or establish interactive TTY behavior. The public proof branch is task-owned and is never merged into the default branch or the upstream PR.
