# Portable Node extraction proof

This branch contains temporary proof assets only. It is not an upstream change or an installer distribution. The workflow runs solely on the named proof branch in `steipete/openclaw`, on a GitHub-hosted `windows-2025` runner, with read-only repository permission and no supplied secrets.

The original source is the complete `scripts/install.ps1` Git blob at `af531525c46444521986002d64b888ee5ed097cb`, SHA-256 `b3203481f6a1dc9fbe73ced87c9ca3b76102a957fefce7c01e6c230db2545875`. The controller removes only the canonical trailing `Main`/`Complete-Install` invocation, using the existing installer test's mechanism, and appends the reviewed extraction fixture. No installer entrypoint, download, Node installation, package installation, or user PATH publication runs. The archive's `node.exe` is plaintext synthetic data; it is never executed.

The after variant changes exactly the existing native tar invocation to `Invoke-CommandFromWindowsSafeDirectory` with the same six arguments. Its full installer hash must be `1d4ba1cafb90a8fd1472ad99687433774441909777728b5470918203117473e2`. This is an independently reviewed data overlay on the frozen original source, not a claim to have tested a future published PR commit. A later candidate must match these production bytes, and the permanent regression still needs canonical CI.

Both Windows PowerShell 5.1 and PowerShell 7 are required. Each runs redirected and unmerged ConsoleHost variants for noisy native failure, quiet native failure, and real system-tar success. The same fixture is used before and after. Before must produce exactly one expected RED: PowerShell 5.1 with explicit PowerShell `2>&1` redirection and noisy exit 17, stopping before fallback publication. The other eleven before cases must pass before the controller admits any after execution. All twelve after cases must pass.

The fixture calls the real extraction owner, shared command wrapper, native `.cmd` process, Windows `tar.exe` success path, and .NET ZIP extractor. It verifies exact native arguments including space-containing paths, native exit status, exact published bytes, fallback branch output, removal of partial native output and extraction temporary directories, and restoration of preference, location and PATH. The after invocation must use the existing safe working directory. Each row runs in a fresh child and fixture directory; the controller retains separate stdout and stderr plus structured verdicts.

Unmerged mode uses ConsoleHost without PowerShell stream merging. GitHub Actions still captures OS handles, so this is an automated ConsoleHost sibling control, not an interactive terminal, ISE, or remoting claim. Each result records host identity and actual stream-redirection facts. PowerShell 7's native-command preference values are observed rather than overridden. A missing engine, setup failure, different original behavior, timeout, excess output, unexpected assertion failure, or incomplete cleanup fails the proof.

Python is the runner's existing process controller; no Python dependency or OpenClaw Node dependency is installed. Candidate PowerShell receives a closed Windows-prerequisite environment plus task-owned temporary paths, without GitHub tokens, cloud credentials or profile loading. Each child has a 30-second limit and a 2 MiB combined output budget. Logs and JSON survive failure; generated executable fixtures and temporary archives are removed before closeout. Downloaded artifacts are evidence data, never scripts to execute on a maintainer host.

The workflow uploads evidence with `always()`. A successful `run.json` requires one expected original RED, eleven passing before controls, twelve passing after cases, and complete workspace cleanup. Source and proof-asset hashes bind that result. There is no workflow-dispatch input, branch merge, publication to the default branch, or automatic PR mutation.

The behavior distinction is documented in [PowerShell #3996](https://github.com/PowerShell/PowerShell/issues/3996) and [Microsoft's preference-variable documentation](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_preference_variables?view=powershell-7.5#erroractionpreference). Those sources guide the matrix; only the observed runner results establish this proof.
