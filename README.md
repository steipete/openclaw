# Two exact-source behavior proofs

This temporary branch runs exact-source proof on GitHub-hosted Ubuntu 24.04 runners. The current matrix runs #132266 through the Node source loader and supported private-QA bootstrap; #127959 already passed all eight Gateway scenarios in [run 33658362660](https://github.com/steipete/openclaw/actions/runs/33658362660). It belongs only on `steipete/openclaw:codex/round10-secretless-proof`; it is not an upstream product or CI change. Pushing the branch starts the selected proof. The manual trigger has no arbitrary source or command inputs. No default-branch change is required.

| PR | Exact candidate commit | Required observed result |
| --- | --- | --- |
| [#127959](https://github.com/openclaw/openclaw/pull/127959) | `378bd531c142e380c5b08265b9d4a37f385f2b56` | Eight Gateway send scenarios, each with one real Baileys-encoded outbound message |
| [#132266](https://github.com/openclaw/openclaw/pull/132266) | `fcb43fa95337a7729814adef36cca18c69bc1ece` | 119 permanent tests, five Gateway QA-channel turns, and six strict-normalizer metadata cases |

The proof assets and candidate source use separate checkouts. Actions are pinned to complete commits; both checkouts disable persisted credentials. The jobs request only read access to repository contents, inject no repository secrets, and use no environment, cloud role, cache restore, or credential hydration. Candidate installation and test subprocesses receive an explicit small environment with fresh HOME, XDG and OpenClaw state paths. The runner is ephemeral; this is not a network firewall or a claim that the test code has no access to the runner filesystem. Network installation uses public package sources; test model and channel services are synthetic and local.

Node 24.19.0 and the repository's complete `pnpm@12.1.0+sha512...` package-manager pin are checked. Corepack is enabled in a private directory, followed by the ordinary `pnpm install --frozen-lockfile`. There are no build-skip flags, dependency overrides, extra retries, worker overrides, or weakened test assertions. The source runner chooses prerequisites using its existing contract. The `.mjs` metadata harness uses the canonical `node --import <candidate>/scripts/tsx.mjs` source loader.

Each job verifies its exact commit and tree, clean tracked source, selected source and dependency file hashes, fixture hash, and installed dependency lock before and after proof. The WhatsApp lane additionally verifies the five inspected Baileys dependency files. The proof source is an untracked test overlay; production files are never edited. Only expected, fully passing Vitest results and complete scenario verdicts count as success. Missing reports, skipped tests, setup failures, changed source, wrong dependency bytes, or cleanup failures fail the job.

Artifacts retain bootstrap/install output, source bindings, exact command receipts, JSON test reports and the bounded proof archive on success or failure. The extractor only reads allowlisted regular files; it never executes archive contents. If checkout or Node setup itself fails before the controller starts, the Actions step log is the evidence and the artifact step warns that there are no controller files. Temporary source overlays and private setup HOME are removed by the controller; hosted runner disposal handles remaining process scratch files.

The #127959 flow exercises authenticated Gateway `send` RPC, the real WhatsApp outbound adapter and real Baileys encoding, with synthetic socket acceptance. It covers group/direct warm, missing and expired quoted-message caches, a media preview and an unquoted send. It does not prove WhatsApp service acceptance, client rendering, inbound network delivery or model inference.

The #132266 flow exercises the QA bus, ordinary QA-channel startup, Gateway admission, actual plugin resolution and normalization, agent execution, tool events and final outbound delivery. The model service is synthetic OpenAI-compatible HTTP. Five cases cover hidden cold/cache-hit/nonenumerable descriptors and visible omitted/false descriptors. Separate six-case metadata proof asserts actual native strict-normalizer cloning, retained metadata, cold/cache reconstruction, lifecycle events and final replies. It does not contact a public model service, Telegram or a Codex process. These behavior results supplement the upstream PR's own exact-head CI; this workflow does not create or impersonate upstream required checks.

The Gateway proof uses Node with the repository source loader and no Vitest loader mocks. It enables the existing private-QA bootstrap setting used by scripts/qa-e2e.ts, allowing the intentional private QA SDK aliases before Gateway startup. Production package exports and sources remain unchanged. Same-run metadata proof binds the actual descriptor cache and normalizer observations; the Gateway verdict separately requires all five channel flows. All behavior assertions and timeouts remain intact.
