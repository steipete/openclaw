# Exact-source automatic WhatsApp reply proof

This temporary, proof-only branch runs one job on GitHub-hosted Ubuntu 24.04. Its fixed destination is `steipete/openclaw:codex/round10-automatic-quote-proof`. It changes no upstream product or CI files and is independent of the already passing eight-scenario Gateway proof in [run 33658362660](https://github.com/steipete/openclaw/actions/runs/33658362660). Root review and publication are required before execution. Pushing this branch starts the proof; the optional manual trigger accepts no arbitrary commands or source references.

The exact candidate is [OpenClaw #127959](https://github.com/openclaw/openclaw/pull/127959), commit `378bd531c142e380c5b08265b9d4a37f385f2b56`, tree `a7dddaf280d73d09acb996202acd2f50fcda121d`. The proof requires all eight ordered group/direct warm, missing and expired cases, a media-preview control and an unquoted control. Every case requires exactly one actual Baileys-encoded message, the full expected body and destination, accepted result/receipt IDs matching the encoded message ID, and the appropriate quote presence/content. Normal cleanup must remove socket listeners, close the socket and leave no pending, claimed or failed ingress rows.

A synthetic external socket is attached through the existing production `attachWebInboxToSocket` entry point. Actual event normalization, admission and SQLite ingress feed the real admitted callback. The test obtains the private production `platform.reply` closure through that callback, calls `createWhatsAppReplyTransportContext` then `deliverWebReply`, and sends through the real socket-session transport into the installed Baileys encoder. Requested quote IDs differ from inbound trigger IDs so automatic trigger caching cannot accidentally warm a target. Expired entries are first read by the production delivery owner.

The preselected reply payload replaces model selection/inference. The socket returns the actual encoded message as synthetic acceptance; it does not contact WhatsApp. This proves automatic delivery and encoding, not a full Gateway inbound/model turn, public WhatsApp service acceptance, client rendering or route/model selection. Fresh temporary SQLite state uses the existing test queue facade; no persistence schema or product configuration changes are made.

The workflow pins all action commits and the Node 24.19.0 distribution, whose bundled Corepack installs the complete repository pnpm 12.1.0 integrity pin. It uses ordinary `pnpm install --frozen-lockfile` and the canonical WhatsApp extension Vitest runner with its existing aliases/prerequisites. Both checkouts disable persisted credentials. There are no repository secrets, cloud roles, hydration, environment approvals, cache restores, dependency overrides, additional retries, runtime overrides or new production settings. The job token only reads the public checkouts. Candidate install and test subprocesses receive an explicit small environment with fresh HOME/XDG/state paths. This is an ephemeral secretless runner, not a network firewall or a claim that code cannot read its runner filesystem.

Before and after proof, the controller checks the exact candidate HEAD/tree, clean tracked source/index, all 58 selected source/manifest/runner hashes, fixture bytes, installed lockfile and five inspected Baileys file hashes. Only the absent untracked proof-test path is overlaid. The driver and separate data-only extractor both require complete native Vitest success and independently validate every case's body, quote, accepted IDs and cleanup; missing, skipped, partial or fabricated pass counts fail. Selected hashes complement full tracked cleanliness; they are not an enumeration of all transitive imports.

Artifacts retain bootstrap/install stdout/stderr, commands/results, source bindings and the allowlisted proof archive on success or failure. The archive has a 64 MiB source envelope; transport/extraction enforce 65 MiB bounds. The extractor admits only named regular files and never executes archive contents. No HOME, auth directory or SQLite database is archived; only synthetic body/quote/receipt projections are recorded, omitting incidental Baileys random reporting bytes. If checkout or Node setup fails before controller startup, the Actions step log is authoritative and artifact upload reports no files. The controller removes its exact untracked overlay and private setup HOME; hosted runner disposal owns remaining process scratch state.

No runtime result is claimed by this branch's source. The existing Gateway result remains separate. The new fixture and controller were prepared without local candidate execution or public writes.
